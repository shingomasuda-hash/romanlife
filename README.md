# ロマンライフ オープン・カンパニー 2026 ｜ 2028年卒向け 採用イベントLP

株式会社ロマンライフの「2028年卒向け オープン・カンパニー」への参加申込みを、
1ページ内で完結させるイベントLPです。外部の求人媒体へは遷移せず、
ページ最下部の専用フォームで **入力 → 確認 → 送信 → 完了** まで行えます。

---

## 1. 起動・ビルド

```bash
npm install
cp .env.example .env.local     # 環境変数を設定（後述）
npm run dev                    # http://localhost:3000
```

```bash
npm run build                  # 本番ビルド
npm start                      # 本番サーバー起動
npm run typecheck              # 型チェック
```

### Vercel への公開

1. リポジトリを Vercel にインポート（フレームワークは Next.js が自動検出されます）
2. **Settings → Environment Variables** に `.env.example` の項目を設定
   - 最低限、`NEXT_PUBLIC_SITE_URL` / `NEXT_PUBLIC_PRIVACY_POLICY_URL` / `ENTRY_WEBHOOK_URL` の3つ
3. Deploy

> Vercel のファイルシステムは読み取り専用のため、申込データの恒久保存には
> `ENTRY_WEBHOOK_URL` を設定してください（未設定でも一時領域へは書き込まれますが、
> 再デプロイで消えます）。

### 公開されるURL

| URL | 中身 |
| --- | --- |
| `/` | **HTML/CSS実装版LP**（`static-lp/` の内容） |
| `/static-lp` | 同上（直接のURL） |
| `/image-lp` | 画像つなぎ版LP（カンプ画像を連結したもの。参考用） |
| `/next-lp` | Next.js版LP（`src/app/page.tsx`） |

`image-lp/` と `static-lp/` は Next.js のビルド対象外のため、`npm run build` の前に
`tools/copy-static.mjs` が `public/` へコピーします（`prebuild` スクリプト）。
`public/image-lp/` `public/static-lp/` はビルド生成物なので Git には含めていません。
**編集するのはリポジトリ直下の `image-lp/` `static-lp/` のほうです。**

トップページの差し替えは `next.config.mjs` の `rewrites().beforeFiles` で行っています。
`index.html` が相対パスで `styles.css` `script.js` `assets/…` を参照しているため、
それらも合わせて `/image-lp/` 配下へ向けています。

```js
beforeFiles: [
  { source: '/', destination: '/static-lp/index.html' },
  { source: '/styles.css', destination: '/static-lp/styles.css' },
  { source: '/script.js', destination: '/static-lp/script.js' },
  { source: '/assets/:path*', destination: '/static-lp/assets/:path*' },
],
```

- **トップをNext.js版に戻す** … 上記 `beforeFiles` を丸ごと削除
- **トップを `image-lp` にする** … 上記4行の `/static-lp/` を `/image-lp/` に置き換え

## 2. 技術構成

| 項目 | 採用したもの | 理由 |
| --- | --- | --- |
| フレームワーク | Next.js 15（App Router）/ React 19 / TypeScript | Route Handler でサーバー側処理を同居させられる |
| スタイル | CSS Modules + CSS カスタムプロパティ | 追加ビルド設定なし。デザイントークンを `globals.css` に集約 |
| バリデーション | Zod（クライアント・サーバー共通スキーマ） | 同じ定義を両側で使い、検証のズレを防ぐ |
| アイコン | 自前の統一SVGセット（`src/components/Icon.tsx`） | 依存を増やさず、線幅・グリッドを揃える。絵文字は不使用 |
| アニメーション | IntersectionObserver + CSS | ライブラリ不要。`prefers-reduced-motion` に対応 |

依存パッケージは `next` / `react` / `react-dom` / `zod` / `server-only` の5つのみです。

### フォント

- **見出し（明朝）**: Shippori Mincho（`next/font/google` でセルフホスト）
- **欧文（セリフ）**: Cormorant Garamond（同上）
- **本文（ゴシック）**: 端末標準のゴシック体（Hiragino Sans / Yu Gothic / Noto Sans JP）

本文に和文Webフォントを使わないことで、読み込みコストを見出しの2書体に抑えています。

## 4. よくある変更作業

### 開催日・時間・締切を変更する

**`src/data/event.ts` の `EVENT_DATES` だけ**を編集してください。
ページ表示、日程カード、フォームの選択肢、確認画面、完了画面、
サーバー側の締切検証、構造化データのすべてが同じデータを参照しています。

### 写真を差し替える

1. 画像を `public/images/` に配置（WebP または AVIF 推奨）
2. `src/data/images.ts` の該当スロットの `src` に `'/images/xxx.webp'` を設定
3. `alt` を実際の写真の内容に合わせて修正

`src` が `null` の間は、**どんな写真を入れるべきか**と**推奨比率・実寸**を表示する
プレースホルダーが出ます。レイアウト領域は先に確保しているため、
差し替えてもレイアウトは崩れません（CLS が発生しません）。

### OGP画像を作り直す

`tools/ogp-template.html` を編集してから：

```bash
node tools/generate-ogp.mjs      # public/ogp.png を再生成（Playwright が必要）
```

### 1ファイルの静的HTMLを書き出す（デザイン共有用）

LP を「外部通信なしで開ける HTML 1枚」に固めて、メール添付やオフライン確認に使えます。

```bash
npm run build && npm start &          # LP を起動しておく
pip install fonttools brotli          # 初回のみ（フォントのサブセット化に使用）
npm i -D playwright                   # 初回のみ
node tools/build-static-preview.mjs   # → preview/romanlife-lp-preview.html
```

CSS をインライン化し、見出しの明朝体はページで実際に使う文字だけへサブセットして
data URI で埋め込むため、1ファイル約 550KB に収まります。

| 含まれるもの | 含まれないもの |
| --- | --- |
| 全セクションの表示・レスポンシブ | 申込フォームの動作（入力→確認→完了） |
| スクロール演出、FAQ の開閉 | 日程カード → フォームへの日程反映 |
| ページ内リンクのスムーズスクロール | 入力エラー表示・締切による選択制御 |

React を同梱しないため、フォームは動作しません。誤って入力されないよう
入力欄は無効化し、冒頭に「デザイン確認用プレビュー」の注記を入れています。
申込機能まで確認する場合は `npm run dev` かデプロイ後のページをご覧ください。

### Google Analytics を追加する

`src/app/layout.tsx` の `<body>` 末尾のコメント箇所に `next/script` でタグを追加してください。
計測イベントは `src/lib/tracking.ts` の `trackEvent()` が `window.dataLayer` へ push します。

計測しているイベント：
`cta_click_hero` / `cta_click_inline` / `schedule_card_click` / `form_view` /
`form_start` / `form_confirm_view` / `entry_complete` / `entry_error`

## 5. 申込フォームの仕組み

### 画面遷移

```
入力 ──「入力内容を確認する」──▶ 確認 ──「この内容で申し込む」──▶ 完了
  ▲                                 │
  └────「入力内容を修正する」────────┘   （入力内容は保持されます）
```

- 送信は「この内容で申し込む」を押したときだけ行われます。
- 送信失敗時は入力内容を保持したまま確認画面に留まり、再試行できます。

### 二重送信の防止（3段構え）

1. 送信中はボタンを `disabled` にし、表示を「送信しています…」へ切り替え
2. クライアント側の `inFlightRef` で多重リクエストを抑止
3. サーバー側で `submissionId` を記憶し、同じIDの再送は**保存せず**同じ結果を返す

### 締切の判定

締切は `2026-08-11T00:00:00+09:00` のように **JST の絶対時刻**で定義しているため、
端末のタイムゾーン設定に関わらず同じ瞬間に締め切られます。

- **画面側**：締切済みの日程はカードのボタンを非表示にし、フォームの選択肢を `disabled` にして「受付終了」を表示（1分ごとに再判定）
- **サーバー側**：`POST /api/event-entry` で毎回再検証。ブラウザのコードを書き換えて
  締切済みの日程を送っても `410` で拒否されます

全日程が締切済みになると、フォーム自体が「本イベントの参加申込み受付は終了しました。」に
切り替わり、APIも受け付けません。

### 保存先

`src/lib/server/storage.ts` の `saveEntry()` が次の2経路へ書き込みます。

| 経路 | 環境変数 | 用途 |
| --- | --- | --- |
| Webhook | `ENTRY_WEBHOOK_URL` | Googleスプレッドシート / 採用管理システム / CRM など。**本番推奨** |
| JSONL ファイル | `ENTRIES_FILE`（既定 `./data/entries.jsonl`） | ローカル検証・自前サーバー |

**どちらにも保存できなかった場合は `500` を返し、利用者に「成功」とは表示しません。**
データベースへ保存する場合は `saveEntry()` に adapter を追加してください。

保存されるのは以下です（管理者が確認できる項目）：
申込日時（JST併記）／参加希望日／参加希望時間／氏名／氏名フリガナ／学校名／
学部・学科・研究科／卒業予定年月／メールアドレス／電話番号／きっかけ／質問／
個人情報同意日時／UTM各種／リファラー／LPのURL／受付番号

### メール通知

`src/lib/server/notify.ts`。環境変数が未設定なら**何もしません**。

- 管理者通知：`ENTRY_NOTIFICATION_EMAIL` を設定すると送信（本文には個人情報を最小限のみ記載）
- 自動返信：`ENTRY_AUTOREPLY_ENABLED=true` かつメール設定済みのときのみ送信

自動返信を送っていない場合、完了画面には「受付完了メールをお送りしました」とは**表示しません**
（実際に送っていない案内を出さないため）。

### スパム・不正対策

| 対策 | 実装 |
| --- | --- |
| ハニーポット | 画面に表示されない `company` 項目。入力があれば拒否 |
| 極端に速い送信 | 表示から3秒未満の送信を拒否 |
| 送信回数制限 | 同一IPから 4秒間隔 / 15分あたり15件まで（大学のPC教室等を考慮した上限） |
| CSRF | `Origin` と `Sec-Fetch-Site` の同一オリジン検証 |
| 入力値の無害化 | HTMLタグ・`javascript:` などを含む入力を拒否（Zod） |
| HTTPS強制 | 本番かつ非ローカルホストで、HTTP のリクエストを拒否 |

> 送信回数制限はプロセス内メモリのため、サーバーレス環境ではインスタンスごとに独立します。
> 本格運用では Vercel KV / Upstash Redis 等の共有ストアへ差し替えてください
> （`src/lib/server/rateLimit.ts` の `hit()` のインターフェースはそのまま使えます）。

### 個人情報の取り扱い

- 個人情報をコンソールへ出力しません
- 個人情報をURLパラメータに含めません
- 入力内容をローカルストレージへ保存しません（UTM情報のみ `sessionStorage` に保持）
- サーバーログに個人情報を記録しません（エラー時も内部情報は返しません）
- クライアント側の値を信用せず、サーバー側で再検証します

- axe-core（WCAG 2.0/2.1 A・AA）：**違反 0件 / 合格 31項目**（1440px・390px の両方）
